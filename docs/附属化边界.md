# 附属化边界

本文记录当前第一阶段的实际边界，后续修改以代码和 `fabric.mod.json` 为准。

## 已迁移到附属模组

- `org.agmas.noellesroles`：角色、修饰符、物品、实体、方块、命令、组件、客户端界面和本地资源。
- `org.agmas.harpymodloader`：本地仍使用的角色权重、禁用管理和组件内容。
- `pro.fazeclan.river.stupid_express`：本地仍使用的角色和注册内容。
- `noellesroles`、`trainmurdermystery` 等旧资源命名空间：保持原 ID，避免旧存档和配置失效。
- `noellesroles.mixins.json` 与 `ricord_rail_express.accesswidener`：仅保留本地内容需要的 Mixin 和访问扩大器。

附属入口是 `io.HuaJiYa.ricordrailexpress.RicordRailExpressAddon`，由 `AddonContent` 统一调用本地 `Noellesroles` 初始化流程。

## 运行时由上游提供

以下内容不再在本项目源码中重复注册或打包，运行时由 `starrailexpress` 提供：

- `io.wifi.starrailexpress` 的角色基类、游戏模式、物品/方块/实体/声音注册表。
- 上游 CCA 组件、事件总线、网络 Payload、回放、地图、商店和客户端渲染工具。
- 上游 `starrailexpress` 命名空间下的资源和数据。

本地源码仍会导入这些上游类。能独立注册的内容优先使用 `api`、`cca`、`event` 等公开接口；现有逻辑还直接引用 `game`、`content`、`index`、`network`、`client`、`util` 等上游实现包，因此不能脱离上游 JAR 单独运行。这正是附属模组的设计边界，不是待打包的缺失文件。

## 兼容策略

- 附属模组使用新 ID `ricord_rail_express`，避免与上游 Mod ID 冲突。
- 本地内容继续使用原有 `noellesroles`、`stupid_express` 等注册 ID；只有未来确认与上游冲突时才迁移具体 ID。
- `libs/starrailexpress.jar` 只用于编译，不进入最终 JAR。版本当前对应上游 `master` 的 `4.4.0`。

## 暂未独立迁移

以下内容仍由上游入口和类负责，第一阶段不复制到附属模组：

1. 上游主入口 `io.wifi.starrailexpress.SRE` 及其客户端入口。
2. 上游基础注册表和基础资源，包括 `TMMItems`、`TMMBlocks`、`TMMEntities`、`TMMSounds`、`TMMParticles` 等。
3. 上游地图、投票、回放、商店、小游戏、任务、皮肤、伪装和网络同步系统。
4. 上游自身的 Mixin、访问扩大器和 `starrailexpress` 命名空间资源。

这些内容没有独立注册入口时，继续通过上游公开 API 使用；后续要拆分时先确认上游是否已有稳定的公开注册接口，再逐项改造。
